# صلاتي — Android

Installable app `com.salati.prayer`, version 1.0.79, Android 8.0+ (API 26), target/compile API 36.

The current Salati interface is bundled locally in a restricted Android WebView, served from an HTTPS asset origin. No hosted Site login is needed inside the APK. Quran text, fonts, images and all adhan/dua recordings work offline. Quran surahs can be downloaded for offline listening; recordings that have not been saved stream on request.

Native features:
- Android geolocation permission delegated to trusted local app origin only.
- Native rotation-vector compass events, with existing JS magnetic-declination correction.
- AlarmManager exact alarms, with user-granted special access and notification permission.
- Media foreground service with alarm audio attributes, audio focus, bounded wake lock, stop action, and adhan followed by optional dua.
- One scheduled next prayer at a time, rescheduled on delivery, boot, app update, system clock change and permission restoration.
- The browser's prayer audio scheduler is disabled in the APK to avoid duplicate adhan.
- More than a year of schedules computed from the same prayer engine, selected city/method and minute adjustments. Open the app periodically to refresh and after force-stop. Update your location after travelling.
- Native home-screen widget with six prayer times and next prayer, click to open app, periodic/time-bound refresh, and optional launcher pin request.

Build:
1. Install Java 17+ (21 used here), Android SDK platform 36 and build-tools 36.
2. In project root: `npm ci`, then `npm run build`.
3. `python scripts/prepare-android.py` copies the current web assets and adjusts native-specific help text. Downloads/build output are excluded.
4. Set `android/local.properties` to the local Android SDK path (not tracked).
5. `cd android && ./gradlew assembleRelease lintRelease`.
6. Align and sign the unsigned APK using your release keystore. The signing identity used for this build is stored outside the repository and is NOT included in source or the APK. Preserve it privately to sign future updates. Never commit it or its password.

Android may suppress background audio after force-stop, revoked permissions, battery restrictions or muted alarm volume. Notifications/exact-alarm permission must be granted by the user; the app never bypasses them. Widget refresh can be deferred by the OS. Online Quran audio availability depends on the original providers.

Adhan audio: previews and scheduled alarms share a native MediaExtractor/MediaCodec → buffered PCM AudioTrack player on a dedicated audio thread. Android software decoders are preferred. A quarter-second prefill and at least half-second output capacity avoid a low-latency WebView audio path. Preview uses media volume; automatic adhan retains alarm usage/audio focus. Stop, audio focus loss, service replacement and completion release decoder/output resources. No recording changes in 1.0.67.

Audio focus (introduced in 1.0.21): notifications that permit ducking reduce playback volume to 25% of the saved preference without stopping; temporary exclusive interruptions pause the PCM track and decoder, retaining queued audio for resume on focus gain. Permanent focus loss still stops playback. Java policy sequence checks: `npm run test:audio-focus` (JDK required).

Silent mode (introduced in 1.0.22): the Android-only saved switch is enabled by default, applies to scheduled adhan (not manual previews), and uses STREAM_ALARM without changing the ringer mode. With a silent/vibrate ringer or zero alarm volume, it raises the alarm stream to at least 60% of its maximum, respecting an explicit zero in-app volume. The previous alarm level is restored after adhan/dua or stop/error unless the user changed it during playback. A persisted restoration record is recovered on the next activity/service/restore-receiver start after process death. MODIFY_AUDIO_SETTINGS is a normal Android permission. Do Not Disturb is not bypassed; users must allow alarms in their DND settings.
